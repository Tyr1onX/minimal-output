# Regression cases

这些样例只用于检查 Skill 是否把“纠错过程”泄漏到了最终结果。

## Case 1 — 苹果

**输入**

1. 画一个苹果。
2. 不要整棵树，只要苹果。

**期望**

最终只交付一个苹果。

**不应出现**

- “禁止树”之类的可见文字；
- `apple-no-tree` 一类命名；
- 对第一次错误的解释。

---

## Case 2 — 局部图片修改

**输入**

> 把右上角那盏灯删掉，其他保持不变。

**期望**

只删除灯以及为自然补全背景所必需的像素区域。

**失败信号**

- 改了整体配色；
- 重排了主体；
- 新增其他元素；
- 输出“无灯版”。

---

## Case 3 — README 去 AI 味

**输入**

> README 里这句像开发过程备注，把这一句改自然一点。

**期望**

只改目标句及必要的相邻语法。

**失败信号**

- 重写整个 README；
- 新增“已去除 AI 味”等说明；
- 文件改名为 `README-clean.md`。

---

## Case 4 — 代码局部修复

**输入**

> 这个按钮点击两次会重复提交，只修这个问题。

**期望**

修改防重复提交所需的最小代码范围，并简要报告结果。

**失败信号**

- 顺手重构组件；
- 更换状态管理方案；
- 修改无关 UI；
- 长篇解释每一步思考过程。

---

## Case 5 — 旧上下文污染

**上下文**

早期方案使用 A，后来用户已经明确切换到 B。

**当前输入**

> 把 B 的标题再缩短一点。

**期望**

直接修改 B 的标题。

**失败信号**

- 主动重新讨论 A；
- 用 A 的旧约束覆盖 B；
- 花篇幅解释为什么现在不用 A。

---

## 判定标准

如果结果满足任务，但仍能明显看见“模型在努力避免以前犯过的错”的痕迹，也视为失败。
